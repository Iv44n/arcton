---
title: Modifying Responses
description: Asignar headers y status desde el middleware, reemplazar el body después de next(), y cuándo la respuesta se vuelve final.
---

`ctx.response` lleva el status y los headers que se van a usar para la
respuesta. El middleware puede leerlo y cambiarlo a la entrada y a la
salida:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.use(async (ctx, next) => {
  await next()
  ctx.response.headers.set('X-Powered-By', 'Arcton')
})

app.get('/', () => ({ ok: true }))

app.listen()
```

## Headers

`ctx.response.headers` es un objeto `Headers` estándar. `set()`
reemplaza, `append()` agrega otro valor:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.use(async (ctx, next) => {
  await next()

  ctx.response.headers.set('X-Request-Id', crypto.randomUUID())
  ctx.response.headers.append('Set-Cookie', 'session=abc; Path=/; HttpOnly')
  ctx.response.headers.append('Set-Cookie', 'theme=dark; Path=/')
})

app.get('/', () => ({ ok: true }))

app.listen()
```

Los cambios de headers funcionan tanto antes como después de
`await next()`, y ambos envían las cookies de arriba. Asignar un
header que el handler también asigna hace que gane la escritura más
tardía, así que un middleware que corre después de `next()` puede
sobrescribir al handler.

## Status

Asigna `ctx.response.status` antes de que el body se produzca — en el
handler, o en un middleware antes de `await next()`:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.post('/users', ctx => {
  ctx.response.status = 201
  ctx.response.headers.set('Location', '/users/42')

  return { id: '42' }
})

app.listen()
```

<Callout type="warn">
  El status queda fijo una vez que se produce el body de la respuesta.
  Asignar `ctx.response.status` después de `await next()` tira un
  `TypeError`. Para cambiar un status a la salida, retorna un valor
  nuevo o un `Response` en su lugar — mira abajo.
</Callout>

## Reemplazar el body después de next()

Retornar un valor después de `await next()` reemplaza el body. Los
headers y el status acumulados hasta ese momento se conservan:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.use(async (ctx, next) => {
  await next()

  return { wrapped: true, at: new Date().toISOString() }
})

app.get('/', () => ({ ok: true }))

app.listen()
```

El cliente recibe el objeto envoltorio.

Para reemplazar también el status, retorna un `Response`. Gana sin
condiciones — no se fusiona ningún header de `ctx.response`:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.use(async (ctx, next) => {
  await next()

  if (ctx.response.headers.get('X-Deprecated') === 'yes') {
    return new Response(JSON.stringify({ error: 'gone' }), {
      status: 410,
      headers: { 'content-type': 'application/json' }
    })
  }
})

app.get('/legacy', ctx => {
  ctx.response.headers.set('X-Deprecated', 'yes')
  return { ok: true }
})

app.listen()
```

## Cortar la cadena

Retornar un valor **sin** llamar a `next()` responde el request de
inmediato, y nada más de la cadena corre:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.use(async (ctx, next) => {
  if (ctx.request.headers.get('x-api-key') !== 'secret') {
    return new Response('Unauthorized', { status: 401 })
  }

  await next()
})

app.get('/private', () => ({ secret: true }))

app.listen()
```

Un corte de cadena también puede retornar un valor simple, que se
mapea de la misma forma que el valor de retorno de un handler:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.use(async (ctx, next) => {
  if (!ctx.request.headers.has('authorization')) {
    ctx.response.status = 401
    return { error: 'missing authorization' }
  }

  await next()
})

app.get('/private', () => ({ secret: true }))

app.listen()
```

## Caché y respuestas condicionales

Como el middleware ve la respuesta a la salida, puede agregar headers
de caché a toda una sección de la API:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.use('/static', async (ctx, next) => {
  await next()
  ctx.response.headers.set('Cache-Control', 'public, max-age=3600')
})

app.get('/static/config', () => ({ theme: 'dark' }))

app.listen()
```

## Ejemplo completo

Timing, un request id y cookies juntos:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.use(async (ctx, next) => {
  const start = performance.now()
  const requestId = ctx.request.headers.get('x-request-id') ?? crypto.randomUUID()

  await next()

  ctx.response.headers.set('X-Request-Id', requestId)
  ctx.response.headers.set(
    'X-Response-Time',
    `${(performance.now() - start).toFixed(2)}ms`
  )
})

app.get('/', ctx => {
  ctx.response.status = 200
  ctx.response.headers.append('Set-Cookie', 'visited=1; Path=/')

  return { ok: true }
})

app.listen()
```

Para ver cómo un valor retornado se convierte en un `Response`, mira
[Response](../fundamentals/response.mdx).
