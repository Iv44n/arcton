## Levantar un servidor

`app.listen()` recibe un objeto de opciones opcional y devuelve un
`RuntimeServer`:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.get('/', () => 'Hello, Arcton!')

app.listen({ port: 8080, hostname: '0.0.0.0' })
```

Llamar a `app.listen()` sin argumentos arranca en el puerto 3000 usando el
adapter de Bun:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.get('/', () => 'Hello, Arcton!')

app.listen()
```

## Elegir un puerto libre

Pasar `port: 0` le pide al sistema operativo un puerto libre en vez de uno
fijo. Lee el puerto real desde el servidor que te devuelve:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.get('/', () => 'Hello, Arcton!')

const server = app.listen({ port: 0 })

console.log(server.port) // an OS-assigned port
console.log(server.url) // e.g. http://localhost:54231/

server.stop()
```

Este es exactamente el patrón que se usa para testear una app real de punta a
punta — consulta [Resumen de testing](../testing/overview.mdx).

## Elegir un adapter

`adapter` selecciona qué runtime sirve la app. El valor por defecto es
`bunAdapter`. Pasa `nodeAdapter` para correr sobre Node.js en su lugar:

```ts
import { nodeAdapter } from '@arcton/adapter-node'
import { Arcton } from '@arcton/core'

const app = Arcton()

app.get('/', () => 'Hello, Arcton!')

app.listen({ adapter: nodeAdapter })
```

Consulta [Adapters](../api/adapters.mdx) para saber qué es un adapter, y
[Soporte de runtime](../introduction/runtime-support.mdx) para las
diferencias concretas entre los dos adapters que vienen incluidos.

## El banner de inicio y el servidor devuelto

`listen()` imprime un banner de inicio — el wordmark de Arcton, seguido de la
versión de Arcton, el nombre y la versión del runtime, la etiqueta de
entorno y la URL en la que está escuchando. La opción `env` controla
solamente esa etiqueta; consulta [Entorno](./environment.mdx) para los
detalles.

Devuelve un `RuntimeServer`:

```ts
interface RuntimeServer {
  readonly port: number
  readonly url: URL
  stop(closeActiveConnections?: boolean): void | Promise<void>
}
```

`stop()` devuelve `void` en el adapter de Bun y un `Promise<void>` en el de
Node, así que siempre es seguro esperarlo con `await`:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.get('/', () => 'Hello, Arcton!')

const server = app.listen({ port: 0 })

await server.stop()
```

Consulta [listen()](../api/listen.mdx) para la referencia completa de la
API.

## Documentar la API

`openapi` activa [`@arcton/openapi`](../integrations/openapi.mdx), un
paquete opcional del que `@arcton/core` no depende:

```ts
import { Arcton } from '@arcton/core'
import { openapi } from '@arcton/openapi'

const app = Arcton()

app.get('/', () => 'Hello, Arcton!')

app.listen({
  openapi: openapi({ info: { title: 'API', version: '1.0.0' } })
})
```

Esto sirve un documento OpenAPI 3.1 en `/openapi.json`, generado a partir de
las rutas registradas para el momento en que corre `listen()`, y una UI de
[Scalar](https://scalar.com) que lo lee en `/docs`. Consulta
[OpenAPI & Scalar](../integrations/openapi.mdx) para la guía completa.

## Apagado elegante

Por defecto, `listen()` drena el servidor al recibir `SIGTERM`/`SIGINT` en
vez de dejar la terminación en manos del comportamiento por defecto del
runtime: deja de aceptar conexiones nuevas, espera a que las requests en
curso terminen (hasta `shutdownTimeout`, 10 segundos por defecto), y luego
sale del proceso. Si una request sigue en curso una vez agotado el timeout,
las conexiones activas se cierran a la fuerza en su lugar.

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.get('/', () => 'Hello, Arcton!')

app.listen({ shutdownTimeout: 5000 })
```

`gracefulShutdown` está pensado para aplicaciones donde Arcton es dueño del
ciclo de vida del proceso — al recibir la señal, llama a `process.exit()`,
que termina *todo* el proceso, no solo este servidor. Ponlo en `false`
cuando la aplicación anfitriona maneja las señales del proceso por su
cuenta (por ejemplo, Arcton incrustado dentro de un proceso más grande, o
un runtime donde las señales del sistema operativo no tienen sentido):

```ts
app.listen({ gracefulShutdown: false })
```

Una segunda `SIGTERM`/`SIGINT` recibida mientras ya se está apagando se
ignora — no inicia un segundo drenaje concurrente.
