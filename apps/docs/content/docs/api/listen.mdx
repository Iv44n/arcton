---
title: listen()
description: Starts serving requests and returns a handle to the running server
---

`listen()` is the last call in an Arcton application:

```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.get('/', () => 'Hello, Arcton!')

const server = app.listen({ port: 3000 })

console.log(`Listening on ${server.url}`)
```

See [Listen options](../configuration/listen-options.mdx) for the usage-first guide.

## listen

**Purpose:** starts the server through the chosen [adapter](./adapters.mdx).

**Signature**
```ts
import type { ArctonListenOptions } from '@arcton/core'
import type { RuntimeServer } from '@arcton/contracts'

declare function listen(options?: ArctonListenOptions): RuntimeServer
```

**Parameters:** an optional `ArctonListenOptions`, documented below.

**Return type:** [`RuntimeServer`](#runtimeserver).

**Behavior:** prints a startup banner — the Arcton figlet logo, the Arcton version, the runtime name and version, the `env`, and the listening URL — then returns a `RuntimeServer`. Routes, `use()`, and `provide()` calls made after `listen()` don't affect requests already flowing through routes registered before it, since each route's pipeline is snapshotted at registration time. Unless `gracefulShutdown` is `false`, it also registers the returned server with a process-wide shutdown coordinator so a `SIGTERM`/`SIGINT` drains it — see [Graceful shutdown](../configuration/listen-options.mdx#graceful-shutdown).

**Errors:** if any [`ws()`](./arcton-app.mdx#ws) route is registered and the chosen adapter's `capabilities.websocket` is `false`, `listen()` throws `Runtime "<adapter.name>" does not support WebSocket routes.`. Both shipped adapters — [`bunAdapter` and `nodeAdapter`](./adapters.mdx) — support WebSockets, so this only matters with a custom adapter. It also throws if `shutdownTimeout` is provided but isn't a positive, finite number.

## ArctonListenOptions

**Purpose:** the options object accepted by `listen()`.

**Signature**
```ts
import type { OpenAPIIntegration, RuntimeAdapter } from '@arcton/contracts'

interface ArctonListenOptions {
  port?: number
  hostname?: string
  adapter?: RuntimeAdapter
  env?: string
  maxBodySize?: number
  openapi?: OpenAPIIntegration
  gracefulShutdown?: boolean
  shutdownTimeout?: number
}
```

**Parameters**

<TypeTable
  type={{
    port: {
      description: 'Port to listen on. 0 picks a free port — read the real one from server.port/server.url.',
      type: 'number',
      default: '3000'
    },
    hostname: {
      description: 'Hostname to bind to.',
      type: 'string'
    },
    adapter: {
      description: 'The RuntimeAdapter used to serve requests.',
      type: 'RuntimeAdapter',
      default: 'bunAdapter'
    },
    env: {
      description: "Labels the startup banner's Environment line. Nothing else reads it.",
      type: 'string',
      default: "process.env.NODE_ENV ?? 'development'"
    },
    maxBodySize: {
      description: 'Max request body size, in bytes.',
      type: 'number',
      default: '134217728 (128MB)'
    },
    openapi: {
      description: 'Serves an OpenAPI document and its UI, from openapi() in @arcton/openapi.',
      type: 'OpenAPIIntegration',
      default: 'undefined'
    },
    gracefulShutdown: {
      description: 'Drains in-flight requests on SIGTERM/SIGINT before calling process.exit().',
      type: 'boolean',
      default: 'true'
    },
    shutdownTimeout: {
      description: 'Max time (ms) to wait for in-flight requests before forcing the close. Must be positive and finite.',
      type: 'number',
      default: '10000'
    }
  }}
/>

**Behavior:** see [Environment](../configuration/environment.mdx) for what `env` does (and only does), [Runtime types](./runtime-types.mdx) for the `RuntimeAdapter` interface, and [Adapters](./adapters.mdx) for the `bunAdapter`/`nodeAdapter` values.

`openapi` is the one field `@arcton/core` accepts without knowing what's on the other end of it — it only knows the [`OpenAPIIntegration`](./openapi.mdx#openapiintegration) interface, never `@arcton/openapi` itself. It's read here, rather than accepted by `Arcton()`, because `listen()` is the first point at which every mounted module is part of the final route tree — the route set an integration documents is the one about to be served. See [OpenAPI & Scalar](../integrations/openapi.mdx).

`gracefulShutdown` and `shutdownTimeout` control the process-wide `SIGTERM`/`SIGINT` handling described in [Graceful shutdown](../configuration/listen-options.mdx#graceful-shutdown). `gracefulShutdown: false` opts a given `listen()` call out entirely — useful when the host application manages process signals itself, since a graceful shutdown ends by calling `process.exit()`, terminating the whole process, not just this server.

## RuntimeServer

**Purpose:** the handle `listen()` returns for the running server.

**Signature**
```ts
interface RuntimeServer {
  readonly port: number
  readonly url: URL
  stop(closeActiveConnections?: boolean): void | Promise<void>
}
```

**Parameters**

<TypeTable
  type={{
    port: { description: 'The bound port.', type: 'number' },
    url: { description: 'The full listening URL.', type: 'URL' },
    closeActiveConnections: {
      description: "Passed to stop() — force-closes in-flight connections instead of waiting for them.",
      type: 'boolean',
      default: 'false'
    }
  }}
/>

**Behavior:** `port` and `url` reflect the address actually bound — useful when `port: 0` picked a free one. `stop()` shuts the server down; it returns `void` on the [Bun adapter](./adapters.mdx) and a `Promise<void>` on the [Node adapter](./adapters.mdx). This is the type used throughout [Testing](../testing/overview.mdx) to start a server on `port: 0`, exercise it with real `fetch` calls, and tear it down afterward.

**Example**
```ts
import { Arcton } from '@arcton/core'

const app = Arcton()

app.get('/', () => 'ok')

const server = app.listen({ port: 0 })

const res = await fetch(server.url)
console.log(res.status, server.port)

await server.stop()
```
