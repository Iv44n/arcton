[Better Auth](https://www.better-auth.com) es una librería de autenticación
independiente del framework. Expone un handler estándar de la Web — una
función que recibe un `Request` y devuelve un `Response` — junto con una
pequeña API de servidor para leer la sesión actual.

Esta guía asume que ya tienes una app de Arcton y una instancia de Better
Auth configurada. Si todavía no configuraste Better Auth, consulta su propia
[guía de instalación](https://www.better-auth.com/docs/installation).

## Instalación

```bash
bun add better-auth
```

```bash
npm install better-auth
```

```bash
pnpm add better-auth
```

## Registrar el handler de Better Auth

El `auth.handler` de Better Auth recibe un `Request` y devuelve un
`Response`. Reenvía cada solicitud bajo tu ruta de autenticación con
[`app.all()`](../routing/http-methods.mdx#every-method-on-one-path):

```ts title="index.ts"
import { Arcton } from '@arcton/core'
import { auth } from './auth'

const app = Arcton()

app.all('/api/auth/*path', ctx => auth.handler(ctx.request))

app.listen()
```

`app.all()` registra el mismo handler para todos los métodos HTTP que
soporta Arcton, así que esta única ruta responde a `GET`, `POST` y el resto
de métodos que necesitan las rutas de Better Auth: registro, inicio de
sesión, cierre de sesión, consulta de sesión, y demás.

Un handler puede devolver un `Response` directamente, y Arcton lo envía tal
cual, así que la respuesta de `auth.handler` llega al cliente sin cambios.
Consulta [Response](../fundamentals/response.mdx) para más detalles.

<Callout>
  `*path` es un [wildcard](../routing/path-parameters.mdx) y requiere al
  menos un segmento, por lo que una solicitud a `/api/auth` sola no
  coincide. Si tu aplicación necesita manejar esa ruta exacta, regístrala
  aparte: `app.all('/api/auth', ctx => auth.handler(ctx.request))`.
</Callout>

## CORS

Si tu frontend corre en otro origen, agrega
[`@arcton/cors`](../middleware/cors.mdx) antes de la ruta de autenticación,
con `credentials: true` para que la cookie de sesión se envíe entre
orígenes. Agrega ese mismo origen a `trustedOrigins` de Better Auth:

```ts title="index.ts"
import { Arcton } from '@arcton/core'
import { cors } from '@arcton/cors'
import { auth } from './auth'

const app = Arcton()

app.use(
  cors({
    origin: 'http://localhost:3001',
    credentials: true,
    allowedHeaders: ['Content-Type', 'Authorization']
  })
)

app.all('/api/auth/*path', ctx => auth.handler(ctx.request))

app.listen()
```

Consulta [CORS](../middleware/cors.mdx) para ver todas las opciones
disponibles.

## Acceder a la sesión en rutas protegidas

Usa `auth.api.getSession()` para leer la sesión actual a partir de los
encabezados de la solicitud, y expón esa información con
[`provide()`](../providers/overview.mdx) para que esté disponible en `ctx`
en cualquier ruta registrada después:

```ts title="index.ts"
import { Arcton } from '@arcton/core'
import { auth } from './auth'

const app = Arcton()
  .provide(async ctx => {
    const session = await auth.api.getSession({ headers: ctx.request.headers })
    return { user: session?.user ?? null, session: session?.session ?? null }
  })

app.all('/api/auth/*path', ctx => auth.handler(ctx.request))

app.get(
  '/me',
  async (ctx, next) => {
    if (!ctx.user) return new Response('Unauthorized', { status: 401 })
    await next()
  },
  ctx => ({ user: ctx.user })
)

app.listen()
```

`ctx.user` y `ctx.session` son `null` cuando no hay una sesión activa.
Agrega un middleware como el de arriba a cualquier ruta que deba requerir
autenticación — puedes aplicarlo por ruta, o con `use()` sobre toda una
sección de rutas.

## Ejemplo completo

```ts title="index.ts"
import { Arcton } from '@arcton/core'
import { cors } from '@arcton/cors'
import { auth } from './auth'

const app = Arcton()
  .use(
    cors({
      origin: 'http://localhost:3001',
      credentials: true,
      allowedHeaders: ['Content-Type', 'Authorization']
    })
  )
  .provide(async ctx => {
    const session = await auth.api.getSession({ headers: ctx.request.headers })
    return { user: session?.user ?? null, session: session?.session ?? null }
  })

app.all('/api/auth/*path', ctx => auth.handler(ctx.request))

app.get(
  '/me',
  async (ctx, next) => {
    if (!ctx.user) return new Response('Unauthorized', { status: 401 })
    await next()
  },
  ctx => ({ user: ctx.user })
)

app.get('/posts', ctx => ({ posts: [], viewer: ctx.user }))

app.listen()
```

Esto funciona igual en Bun y en Node — Arcton entrega a `auth.handler` un
`Request` estándar en cualquiera de los dos runtimes.
