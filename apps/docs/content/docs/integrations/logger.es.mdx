title: Logging

`@arcton/logger` loguea una línea por request — método, path, status,
duración — a través de [Pino](https://getpino.io). Es un único middleware:
ninguna configuración vive en `Arcton()` ni en `listen()`, y `@arcton/core`
nunca importa Pino.

## Uso básico

```ts title="index.ts"
import { Arcton } from '@arcton/core'
import { logger } from '@arcton/logger'

const app = Arcton()

app.use(logger())

app.get('/users/:id', ctx => ({ id: ctx.params.id }))

app.listen()
```

Cada request ahora produce una línea de JSON, una vez que se conoce la
respuesta:

```json
{"level":30,"time":1234567890,"method":"GET","path":"/users/1","status":200,"durationMs":0.4,"msg":"GET /users/1 200 0.4ms"}
```

## Por qué `app.use()` y no `listen()`

Se registra exactamente igual que [`@arcton/cors`](../middleware/cors.mdx)
— no existe una opción `listen({ logger })`, a propósito. Los pasos de
`use()` quedan fijados en cada ruta en el momento en que se registra (ver
[Orden de ejecución](../middleware/execution-order.mdx)); un hook que solo
se disparara desde dentro de `listen()` correría después de que cada ruta
ya tiene su pipeline fijado, así que nunca podría envolver un request de
verdad. Un access log por request solo tiene sentido como middleware,
registrado antes de las rutas que debe cubrir.

## El status decide el nivel

```ts
import { Arcton } from '@arcton/core'
import { logger } from '@arcton/logger'

const app = Arcton()

app.use(logger())

app.get('/ok', () => ({ ok: true })) // logueado a info
app.get('/missing', ctx => {
  ctx.response.status = 404 // logueado a warn (4xx)
  return { error: 'not found' }
})
app.get('/boom', () => {
  throw new Error('kaboom') // logueado a error
})

app.listen()
```

Una respuesta `2xx`/`3xx` se loguea a `info`, una `4xx` a `warn`, una `5xx`
a `error` — ningún handler tiene que loguear nada por su cuenta. Si un
request falla y nada aguas abajo captura el error, el logger lo loguea a
`error` con el error adjunto y vuelve a lanzarlo sin modificarlo, así que
el manejo de errores (un handler de
[`onError()`](../errors/global-error-handler.mdx), o ninguno) se comporta
exactamente igual que sin el logger.

## Pretty-printing

`pretty: true` formatea los logs para que los lea una persona en vez de
JSON separado por líneas, a través del transport oficial de Pino,
[`pino-pretty`](https://github.com/pinojs/pino-pretty):

```ts
import { Arcton } from '@arcton/core'
import { logger } from '@arcton/logger'

const app = Arcton()

app.use(logger({ pretty: process.env.NODE_ENV !== 'production' }))

app.get('/', () => 'ok')

app.listen()
```

`pino-pretty` es una peer dependency, no una dependencia regular — nunca
forma parte de las dependencias de producción propias de `@arcton/logger`.
Instalala vos mismo donde quieras salida pretty:

<Tabs items={['bun', 'npm', 'pnpm', 'yarn']}>
<Tab value="bun">

```bash
bun add -D pino-pretty
```

</Tab>
<Tab value="npm">

```bash
npm install -D pino-pretty
```

</Tab>
<Tab value="pnpm">

```bash
pnpm add -D pino-pretty
```

</Tab>
<Tab value="yarn">

```bash
yarn add -D pino-pretty
```

</Tab>
</Tabs>

Sin instalarlo, `logger({ pretty: true })` lanza el mismo error que
lanzaría Pino por un transport faltante — en el setup, no por request.

## Traer tu propia instancia de Pino

Pasa `instance` para usar un logger de Pino que ya construiste — para una
app que centraliza su propia configuración de Pino (redacción, serializers
propios, un destination compartido) fuera de Arcton:

```ts
import { Arcton } from '@arcton/core'
import { logger } from '@arcton/logger'
import pino from 'pino'

const instance = pino({ redact: ['req.headers.authorization'] })

const app = Arcton()

app.use(logger({ instance }))

app.get('/', () => 'ok')

app.listen()
```

`level`/`pretty`/`pino` se ignoran cuando se da `instance` — se usa
exactamente el logger que construiste.

## Loguear fuera del ciclo de request

`logger()` devuelve el middleware con la instancia de Pino subyacente
agregada como `.pino`, así que el mismo logger se puede usar en cualquier
otro lugar de tu app — por ejemplo, justo después de `listen()`:

```ts
import { Arcton } from '@arcton/core'
import { logger } from '@arcton/logger'

const app = Arcton()
const log = logger()

app.use(log)
app.get('/', () => 'ok')

const server = app.listen({ port: 0 })
log.pino.info(`listening on ${server.url}`)
```

Ver [`logger()`](../api/logger.mdx) para la referencia completa de la API.
